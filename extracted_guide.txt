1. What You Will Learn This Week
You start with an empty Laravel install and end with a small course catalogue that has two separate security layers: authentication (who are you?) and authorization (what are you allowed to do?). Laravel Breeze gives you a complete login system in minutes. You then write the rules yourself with gates, a policy, and a simple role system.
Learning competencies:
Distinguish authentication from authorization; understand session and token guards.
Implement authentication with a starter kit (Laravel Breeze) and protect routes.
Authorize actions with gates and policies; manage simple roles.
Assessment: Quiz 8 and Lab Exercise 8 (an auth-protected application with a policy that enforces resource ownership, plus a simple role check).

Guards
A guard defines how users are authenticated on each request. The web guard uses the session: a cookie identifies the logged-in user. The sanctum (API) guard uses a bearer token in the Authorization header, which is what APIs use. Both are configured in config/auth.php. This week uses only the web guard.

3. Part A: Authentication with Laravel Breeze
3.1 Install Breeze
Install Breeze first, before writing any routes or views
breeze:install overwrites routes/web.php, the layouts and some config files. Anything you wrote there before installing Breeze is lost. That is why this guide installs Breeze immediately, on the clean project, and builds the Course feature afterwards.
 RUN IN TERMINAL

Passing blade selects the Blade with Alpine stack and skips the questions (no dark mode, PHPUnit tests). This matches what you have learned so far.
breeze:install runs npm install and npm run build for you. Wait until you see "Breeze scaffolding installed successfully".
php artisan migrate will say "Nothing to migrate". That is correct: the tables Breeze needs (users, password_reset_tokens, sessions) already exist.

3.4 What happens on login
LoginRequest validates the email and password and checks the throttle (5 attempts per minute per email + IP).
Auth::attempt($credentials, $remember) finds the user by email and verifies the hashed password.
On success the session ID is regenerated (this prevents session fixation) and the user's ID is stored in the session.
On every later request the web guard reads the session cookie and loads the User model, available as auth()->user() or $request->user().
If the user was sent to /login by the auth middleware, redirect()->intended() returns them to the page they originally asked for.
Passwords
Never store plain passwords. Laravel hashes them with bcrypt through the 'password' => 'hashed' cast on the User model. Never compare passwords with ==. Always use Hash::check() or Auth::attempt().

4.2 Migrations
Role column on users. Every user gets a role. New registrations are student by default; the other roles are instructor and admin. Part C uses this column. In MySQL, ->after('email') places the new column right after email.
 REPLACE ENTIRE FILE    database/migrations/xxxx_xx_xx_xxxxxx_add_role_to_users_table.php
<?php
 
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;
 
return new class extends Migration
{
    public function up(): void
    {
        Schema::table('users', function (Blueprint $table) {
            // student | instructor | admin
            $table->string('role', 20)->default('student')->after('email');
        });
    }
 
    public function down(): void
    {
        Schema::table('users', function (Blueprint $table) {
            $table->dropColumn('role');
        });
    }
};
Courses table. user_id stores the course owner. constrained() adds a real MySQL foreign key to users.id, and cascadeOnDelete() makes MySQL delete a user's courses when the user is deleted.
 REPLACE ENTIRE FILE    database/migrations/xxxx_xx_xx_xxxxxx_create_courses_table.php
<?php
 
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;
 
return new class extends Migration
{
    public function up(): void
    {
        Schema::create('courses', function (Blueprint $table) {
            $table->id();
            $table->foreignId('user_id')            // the owner (instructor)
                  ->constrained()
                  ->cascadeOnDelete();
            $table->string('code', 20)->unique();
            $table->string('title');
            $table->unsignedTinyInteger('units')->default(3);
            $table->boolean('is_active')->default(true);
            $table->timestamps();
        });
    }
 
    public function down(): void
    {
        Schema::dropIfExists('courses');
    }
};
Enrolment pivot table. This links students to the courses they take. The policy in Part C uses it: an instructor cannot delete a course that has students.
 REPLACE ENTIRE FILE    database/migrations/xxxx_xx_xx_xxxxxx_create_course_user_table.php
<?php
 
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;
 
return new class extends Migration
{
    public function up(): void
    {
        // Pivot table: which students are enrolled in which course
        Schema::create('course_user', function (Blueprint $table) {
            $table->id();
            $table->foreignId('course_id')->constrained()->cascadeOnDelete();
            $table->foreignId('user_id')->constrained()->cascadeOnDelete();
            $table->timestamps();
 
            $table->unique(['course_id', 'user_id']);
        });
    }
 
    public function down(): void
    {
        Schema::dropIfExists('course_user');
    }
};
4.3 Models
Replace the generated User model. It adds the two relationships and the role helpers used later.
 REPLACE ENTIRE FILE    app/Models/User.php
<?php
 
namespace App\Models;
 
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Relations\BelongsToMany;
use Illuminate\Database\Eloquent\Relations\HasMany;
use Illuminate\Foundation\Auth\User as Authenticatable;
use Illuminate\Notifications\Notifiable;
 
class User extends Authenticatable
{
    use HasFactory, Notifiable;
 
    // 'role' is deliberately NOT fillable: a user must never be able
    // to promote themselves by adding role=admin to a form.
    protected $fillable = ['name', 'email', 'password'];
 
    protected $hidden = ['password', 'remember_token'];
 
    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed',
        ];
    }
 
    // Courses this user OWNS (teaches)
    public function courses(): HasMany
    {
        return $this->hasMany(Course::class);
    }
 
    // Courses this user is ENROLLED in (as a student)
    public function enrolledCourses(): BelongsToMany
    {
        return $this->belongsToMany(Course::class)->withTimestamps();
    }
 
    // ---- Role helpers (used in Part B and Part C) ----
    public function isAdmin(): bool
    {
        return $this->role === 'admin';
    }
 
    public function isInstructor(): bool
    {
        return $this->role === 'instructor';
    }
 
    public function hasRole(string ...$roles): bool
    {
        return in_array($this->role, $roles, true);
    }
}
Laravel 13 note
Laravel 13 generates the User model with #[Fillable] / #[Hidden] attributes instead of $fillable / $hidden properties. Both styles work in Laravel 13. This guide uses the properties so that the same file also works in Laravel 12.
 REPLACE ENTIRE FILE    app/Models/Course.php
<?php
 
namespace App\Models;
 
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;
use Illuminate\Database\Eloquent\Relations\BelongsToMany;
 
class Course extends Model
{
    use HasFactory;
 
    // user_id is NOT fillable: the owner is always set on the server
    protected $fillable = ['code', 'title', 'units', 'is_active'];
 
    protected function casts(): array
    {
        return [
            'is_active' => 'boolean',
        ];
    }
 
    public function owner(): BelongsTo
    {
        return $this->belongsTo(User::class, 'user_id');
    }
 
    public function students(): BelongsToMany
    {
        return $this->belongsToMany(User::class)->withTimestamps();
    }
}
Mass assignment: why user_id and role are not fillable
Anything in $fillable can be set from form input. If role were fillable, a user could add role=admin to the registration form with the browser dev tools. If user_id were fillable, a user could create courses in someone else's name. Set these values on the server instead.

4.5 Form Request
Rule::unique(...)->ignore(...) lets a course keep its own code when you edit it, but still rejects a code that another course already uses. authorize() returns true for now. Part C turns it into a real check.
 REPLACE ENTIRE FILE    app/Http/Requests/CourseRequest.php
<?php
 
namespace App\Http\Requests;
 
use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Validation\Rule;
 
class CourseRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true; // Part C replaces this with a policy check
    }
 
    public function rules(): array
    {
        return [
            'code'      => [
                'required', 'string', 'max:20',
                Rule::unique('courses', 'code')->ignore($this->route('course')),
            ],
            'title'     => ['required', 'string', 'max:255'],
            'units'     => ['required', 'integer', 'between:1,6'],
            'is_active' => ['boolean'],
        ];
    }
}
4.6 Controller
Look at store(): the owner is taken from the logged-in user through the relationship. The form never sends a user_id, and even if someone adds one by hand, it is ignored.
 REPLACE ENTIRE FILE    app/Http/Controllers/CourseController.php
<?php
 
namespace App\Http\Controllers;
 
use App\Http\Requests\CourseRequest;
use App\Models\Course;
 
class CourseController extends Controller
{
    public function index()
    {
        $courses = Course::with('owner')->orderBy('code')->get();
 
        return view('courses.index', compact('courses'));
    }
 
    public function create()
    {
        $course = new Course(['units' => 3, 'is_active' => true]);
 
        return view('courses.form', compact('course'));
    }
 
    public function store(CourseRequest $request)
    {
        // The owner comes from the logged-in user, NEVER from the form
        $course = $request->user()->courses()->create($request->validated());
 
        return redirect()->route('courses.show', $course)
            ->with('status', 'Course created.');
    }
 
    public function show(Course $course)
    {
        $course->load('owner')->loadCount('students');
 
        return view('courses.show', compact('course'));
    }
 
    public function edit(Course $course)
    {
        return view('courses.form', compact('course'));
    }
 
    public function update(CourseRequest $request, Course $course)
    {
        $course->update($request->validated());
 
        return redirect()->route('courses.show', $course)
            ->with('status', 'Course updated.');
    }
 
    public function destroy(Course $course)
    {
        $course->delete();
 
        return redirect()->route('courses.index')->with('status', 'Course deleted.');
    }
}

5. Part C: Authorization
5.1 Gates (simple, closure-based)
A gate is a named yes/no rule. It suits checks that are not about one particular model, like "may this user manage users?". Gates are defined in AppServiceProvider::boot(). You add a real one in §5.2. This is how they are defined and checked:
 REFERENCE ONLY - DO NOT PASTE 
use Illuminate\Support\Facades\Gate;
 
// Define (in AppServiceProvider::boot)
Gate::define('manage-users', fn (User $user) => $user->isAdmin());
Gate::define('edit-course', fn (User $user, Course $course) => $user->id === $course->user_id);
 
// Check
if (Gate::allows('edit-course', $course)) { /* ... */ }
if ($request->user()->can('edit-course', $course)) { /* ... */ }
Gate::authorize('manage-users');            // throws -> 403 Forbidden
 
// Blade
@can('edit-course', $course) <a href="...">Edit</a> @endcan
When a model has several rules (view, create, update, delete), put them in one policy class instead of many gates. That is §5.3.

<?php
 
namespace App\Http\Middleware;
 
use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;
 
class EnsureUserHasRole
{
    /**
     * Usage in routes: ->middleware('role:admin') or 'role:instructor,admin'
     */
    public function handle(Request $request, Closure $next, string ...$roles): Response
    {
        if (! $request->user() || ! $request->user()->hasRole(...$roles)) {
            abort(403, 'You do not have the required role.');
        }
 
        return $next($request);
    }
}

5.3 Policies (one class per model)
Generate the policy:
 RUN IN TERMINAL 
php artisan make:policy CoursePolicy --model=Course
Replace it with the rules from the specification in §1.1:
 REPLACE ENTIRE FILE    app/Policies/CoursePolicy.php
<?php
 
namespace App\Policies;
 
use App\Models\Course;
use App\Models\User;
 
class CoursePolicy
{
    /**
     * Runs before every other method.
     * true = allow, false = deny, null = "no opinion, run the normal method".
     */
    public function before(User $user, string $ability): ?bool
    {
        return $user->isAdmin() ? true : null;
    }
 
    // ?User means guests are allowed to reach this check
    public function viewAny(?User $user): bool
    {
        return true;
    }
 
    public function view(?User $user, Course $course): bool
    {
        // Active courses are public; inactive ones only for their owner
        return $course->is_active || ($user && $user->id === $course->user_id);
    }
 
    public function create(User $user): bool
    {
        return $user->hasRole('instructor', 'admin');
    }
 
    public function update(User $user, Course $course): bool
    {
        return $user->id === $course->user_id;
    }
 
    public function delete(User $user, Course $course): bool
    {
        // Owners may delete only courses with no enrolled students
        return $user->id === $course->user_id
            && $course->students()->doesntExist();
    }
}
How it is found: Laravel auto-discovers App\Policies\CoursePolicy for App\Models\Course because of the naming convention, so there is nothing to register. before() runs first: true allows, false denies, and null means "no opinion, run the normal method". ?User (nullable) lets guests reach viewAny and view. For methods with a plain User parameter, guests are denied automatically.
5.4 Enforce the policy in the controller
Each action calls Gate::authorize(ability, model). If the policy says no, Laravel stops the request with 403 Forbidden.
 REPLACE ENTIRE FILE    app/Http/Controllers/CourseController.php
<?php
 
namespace App\Http\Controllers;
 
use App\Http\Requests\CourseRequest;
use App\Models\Course;
use Illuminate\Support\Facades\Gate;
 
class CourseController extends Controller
{
    public function index()
    {
        Gate::authorize('viewAny', Course::class);
 
        $courses = Course::with('owner')->orderBy('code')->get();
 
        return view('courses.index', compact('courses'));
    }
 
    public function create()
    {
        Gate::authorize('create', Course::class);
 
        $course = new Course(['units' => 3, 'is_active' => true]);
 
        return view('courses.form', compact('course'));
    }
 
    public function store(CourseRequest $request)
    {
        Gate::authorize('create', Course::class);
 
        // The owner comes from the logged-in user, NEVER from the form
        $course = $request->user()->courses()->create($request->validated());
 
        return redirect()->route('courses.show', $course)
            ->with('status', 'Course created.');
    }
 
    public function show(Course $course)
    {
        Gate::authorize('view', $course);
 
        $course->load('owner')->loadCount('students');
 
        return view('courses.show', compact('course'));
    }
 
    public function edit(Course $course)
    {
        Gate::authorize('update', $course);   // 403 if denied
 
        return view('courses.form', compact('course'));
    }
 
    public function update(CourseRequest $request, Course $course)
    {
        Gate::authorize('update', $course);
 
        $course->update($request->validated());
 
        return redirect()->route('courses.show', $course)
            ->with('status', 'Course updated.');
    }
 
    public function destroy(Course $course)
    {
        Gate::authorize('delete', $course);
 
        $course->delete();
 
        return redirect()->route('courses.index')->with('status', 'Course deleted.');
    }
}
Why not $this->authorize() or authorizeResource()?
Since Laravel 11 the base app/Http/Controllers/Controller.php is empty. $this->authorize() only works after you add use Illuminate\Foundation\Auth\Access\AuthorizesRequests; and use AuthorizesRequests; to that base class.
$this->authorizeResource(Course::class, 'course') in a constructor no longer works even with the trait: it fails with "Call to undefined method CourseController::middleware()". Use Gate::authorize() in each method, as above.
Ability names to remember: index → viewAny, show → view, create/store → create, edit/update → update, destroy → delete.
5.5 Enforce it in the Form Request too
A Form Request's authorize() runs before validation. Returning false gives a 403 without even validating the input.
 REPLACE ENTIRE FILE    app/Http/Requests/CourseRequest.php
<?php
 
namespace App\Http\Requests;
 
use App\Models\Course;
use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Validation\Rule;
 
class CourseRequest extends FormRequest
{
    public function authorize(): bool
    {
        // a Course model when updating, null when creating
        $course = $this->route('course');
 
        return $course
            ? $this->user()->can('update', $course)
            : $this->user()->can('create', Course::class);
    }
 
    public function rules(): array
    {
        return [
            'code'      => [
                'required', 'string', 'max:20',
                Rule::unique('courses', 'code')->ignore($this->route('course')),
            ],
            'title'     => ['required', 'string', 'max:255'],
            'units'     => ['required', 'integer', 'between:1,6'],
            'is_active' => ['boolean'],
        ];
    }
}
